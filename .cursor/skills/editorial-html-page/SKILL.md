# 分页 HTML（分屏）

这是**分页 / 分屏**模板。流式长文规整是另一套：`templates/editorial-flow/`，skill 是 `editorial-html-normalize`。两套不能互切：不要加载 `flow.css`，不要加「流式阅读」按钮，不要把 `.is-deck` 改成 `.is-flow`。

报告的原子是听众的一步。演示的原子是一个父组件。抄演示的 markup，不抄演示的切法。

先读原文，写成带章节树、正文和图链的 Markdown，再按这份稿套模板。不要先挑组件，也不要按源目录的外形开 tab。

用户只要组织：交 Markdown 参考稿后停。用户要页：稿经确认（或对方说直接做）再写 `Outputs/<slug>/index.html`。HTML 只许从这份稿填，不许绕过它从源文件切片。稿和页必须是同一套；页若已存在，以稿为准重套，不要两份各改各的。

## 两套语法（禁止混用）

| | 演示页 `states-demo` | 报告 |
|---|---|---|
| 一屏是什么 | 穷举一种组件状态 | 做完听众的一个问句 |
| 标题下 `__part` | 可以写组件名 | 只放比主标题弱的范围或条件；没有就删 |
| 同一问里的多个同类对象 | 各占一屏，把组件走一遍 | 一屏并排，一次看完 |
| 怎么用它 | 抄 class 和结构 | 抄 class 和结构，不抄分页节奏 |

把演示的切法带进报告，就是把组件名写进标题、把同一问拆成逐个组件屏。

## 1. 内容组织

组织的不是文件，是听众脑子里的一条路：进门时不知道该信什么，出门时知道这件事是什么、凭什么、接下来怎么办。

源标题是作者怎么归档的，不是听众要走的路。读懂每一块在回答哪一问、担任什么角色，再精确成树。

| 这块在干什么 | 在树上的位置 |
|---|---|
| 立一个主张 | 自己成章，或做一章的开场 |
| 给某个主张付账 | 挂在那个主张下面，不另占导航 |
| 收成：现在该怎么办 | 自己成章。这是另一问 |
| 边界：材料不能支撑什么 | 自己成章，放在最后 |

读不准就标「待确认」并停问。不要用源标题平级当理解，也不要为了导航更短拿掉一整问。

### 章节树

分章是先画枝，不是先开 tab。导航从树长出来。树没梳清，不要切屏。导航写能看懂的章名，不要截成固定字数。选中用导航自己的皮肤，点击后不要留下浏览器描边。

**付账还是另一问，用这一句分：** 把这块单独抽出来，听众要完成的问句变了没有？

- 没变，只是数字、规则、现场、样本在给同一句付账 → 挂在这枝下面。
- 变了 → 另起一枝。兄妹是不同的问，不是孙节点。

禁止把父问句写宽来把另一问装进去。那不是付账，是合并。为了少开一档导航而合并，也算挂错。

回验：任一枝单独抽出来，问句还能否成立；整场标题连起来，能否听出一条路。

### 主判断怎么选

听众走出去能复述的一句。优先用原文。原文没有或有好几句都像，标「待确认」并停问。后面所有章都在给它付账。不要另写汇报腔，不要改数字和判断的松紧。

### 每一页怎么起标题

翻页时你先开口说一句，再让他们看。`__title` 就是那一句，不是这页的名字。

整场标题连起来，应该能听出一条路。抽掉图和表只念标题，听众还知道你要他们信什么。念完像目录、像字段、像把表读了一遍，这页还没起好。

一页只配一句。这句是判断、转折或取舍，有主语、有动作。他们离开时只记得大字，必须已经得到这页该给的东西。

| 槽 | 听众拿它当什么 | 往里放什么 |
|---|---|---|
| `__no` | 我现在在哪一章 | 章号 + 题域。分类名停在这里 |
| `__title` | 翻上来你开口那一句 | 能讲出口的判断、转折或取舍 |
| `__part` | 这句的范围或条件 | 比主标题弱的一句；没有就删 |

找标题的顺序不能反：

1. 先看这一屏材料，问：离开时只记得一句，应该是哪句。
2. 出声念。念不利索、要停下来解释这是什么意思，就还不是标题。
3. 回原文找作者已经写出来的判断。没有就待确认，不要编汇报腔。
4. 题域进 `__no` 或章封面。一屏一句，各自找，不要把章题复制到每一屏。

数字可以上标题，只在数字本身就是那一击的时候，并且说成人话里的多少、多贵、多窄。比较的维度、口径缩写、样本价、字段名是下面的证据，不抬到大字上。列名是表头的事，不要写进 `__part` 去顶包。

回验：只看大字，是不是人话，是不是这页该给的东西。大字是分类或维度清单、小字才是判断 → 槽位用反了。大字和材料对不上 → 用了邻屏或整章的句子。

### 强调级别

视觉重量必须等于命题重量。先问这一屏的任务，再选皮肤。

判断句：拿掉反色之后，听众是否少做了一个必须做的决定？是 → 强调。否 → 默认。拿不准 → 默认。

| 这一屏要听众干什么 | 重量 | 形式 |
|---|---|---|
| 改一个判断，只要一句 | 强调 | Decision Callout |
| 改判断，且必须并排钉住几句 | 强调 | 观点 / 带序号观点，多格并排 |
| 看懂并列事实、属性、对照、步骤 | 默认 | 数据、列表、编号列表、表、条 |

强调不是「这章比较重要所以涂色」，也不是「章末自动升级」。默认皮肤能完成的任务，不要升级。重量用上面的判断句决定，不要在稿末用屏号清单规定谁用强调。

### 单屏

一屏一个问句，也只装一种 Content。同一问的同类对象用多格并排。一个形式装不下，就换屏，不要在一个 Grid 里叠两种 Content。

图和字抢注意力，就选边：必须看清图 → 图当主角；必须读完字 → 字当主角；图是场景、字是一句判断 → 全屏有图；论证抽象 → 不要图。旁边的字离开图就不能成立，那是图注，不是全屏。

## 2. 参考稿（先写这个）

基于原文和大纲，先写 `Outputs/<slug>/report.md`。没有这份稿，禁止写 HTML。

稿里每一节点必须有：问句、能讲出口的结论、任务、注意力、重量、形式、正文、图的路径和说明。图链从原文 `src` / `data-src` / `data-lightbox-src` 收，再用 `find` 核磁盘；不要用 Glob 碰运气。

```markdown
# [报告名]

主判断：…

## 章节树

- 00 封面
- 01 [问句] · 主张
  - 01.a [开口那一句]
- 02 [问句] · 主张
- … 收成
- … 边界

## 01 [题域]

问句：
判断：

### 01.a

问句：
结论：
任务：判断 / 证据 / 比较 / 步骤 / 尺度 / 换气
注意力：图当主角 / 字当主角 / 图当底 / 只要字
重量：默认 / 强调
形式：
正文：
- …
图：
- `assets/…` — 说明
```

磁盘有、文中无的图：复制进 `assets/`，在稿里标缺口。听众没说拍板还是对齐事实，按对齐事实写，不加判断腔。

只组织：把这份稿交给用户，停。要页：按稿套模板，不按源 HTML 的外形切。不要在稿末另写一套「这些屏用强调、那些屏改标题」的清单，判断写在每一节点上。

## 3. 页面与父组件

形式跟着问句走。markup 从 `templates/editorial-page/` 抄壳。这是分屏：`.report-shell.is-deck`，带标题栏和翻页。不要抄 `templates/editorial-flow/`。模板按分页穷举父组件：标题是组件名，副题是使用场景。报告抄 class 和结构，不要按它一组件一屏切。Evidence 多一种比例时打开 `templates/draft/editorial-flow/states-demo/`。样式拷到 `Outputs/<slug>/lib/`：`template.css`、`template.js`，以及 `templates/shared/` 的 `components.css`、`theme-runtime.js`、`design-data.js`。再从仓库根 `editor/` 拷 `seed-edit.css` / `seed-edit.js` 到 `lib/editor/`，在 HTML 引入；不要靠 `template.js` 里的旧白名单编辑器。不要拷 `flow.css`。不要输出去读 `../../design-system/`。

先选分页，再往格子里放**一种** Content。一个 `.page-grid` 只放一种。不要发明新的分页，也不要在一个格子里叠两种 Content。`report-section__stack`、`report-split`、`.block-set` 不是分页，不要抄。

三层不要混：Content 是格里的东西；Grid 1–4 是同一 Content 在不同格宽里的适配；分页是这一屏几格、是不是全屏。

### 分页（只有这些）

| 分页 | markup | 这一屏是什么 |
|---|---|---|
| 封面 | `.report-cover` | 整场开场。壳，没有格子 |
| 章封面 | `.chapter-cover` | 换气。壳，没有格子 |
| 口径 | `.report-notes` | 边界。最后一章，导航里有这一档。壳，没有格子 |
| 非全屏 1 | `.page-grid[data-slots="1"]` | 一格，Grid 1，铺满内容区 |
| 非全屏 2 | `.page-grid[data-slots="2"]` | 两格，Grid 2，对等并排 |
| 非全屏 3 | `.page-grid[data-slots="3"]` | 三格，Grid 3，对等并排 |
| 非全屏 4 | `.page-grid[data-slots="4"]` | 四格，Grid 4，2×2 |
| 非全屏 5 | `.page-grid[data-slots="5"]` | 五格，3 列折两行，末行两格居中 |
| 非全屏 6 | `.page-grid[data-slots="6"]` | 六格，3×2 |
| 非全屏 7–9 | `.page-grid[data-slots="7"]` / `8` / `9` | 更密的 3 列 3 行，一次铺开 |
| 非全屏 10+ | `.page-grid[data-slots="10"]` | 多格横滑，复用 Grid 3 |
| 全屏 · 有图 | `.full-page[data-full="image"]` | 图铺满当底，中间一块 Content |
| 全屏 · 无图 | `.full-page[data-full="none"]` | 浅底，一块 Content |

全屏永远 1 块，不是 Grid 的第 6、7 种分组。选分页仍按问句，不要为了用上全屏硬切。不要按条数自动换列，也不要用 `.block-set` 表示多组。

### Content（格子里的父组件）

| Content | `data-content` | 什么时候用 | 一格是什么 |
|---|---|---|---|
| 纯文字 | `copy` | 只读书面说明 | 标题 + 正文 |
| 观点 | `point` | 改一个判断，只要一句 | 结论 + 一句 |
| 带序号观点 | `signal` | 并列要点，一卡一眼 | SIGNAL + 标题 + 说明 |
| 数据 | `stat` | 尺度。数字行只放数字或符号 | 大数字 + 名 + 口径 |
| 列表 | `list` | 属性、规则、条目 | **一条**：标签 + 说明 |
| 编号列表 | `step` | 有先后的步骤 | **一步**：序号在左 |
| 编号列表纵向 | `step-stack` | Grid 3 / 5–9 / 10+ 的编号列表 | **一步**：序号压在标题上 |
| 表格 | `table` | 比较表 / 明细表 | 整表。宽和长只差行列数 |
| Bar | 格内 `.bar-compare` | 同类量比较 | 一组条 + **组标题** |
| Evidence | `.image-grid.evidence-gallery` | 图 + 图注 | 不进 Grid 格 |
| Media Switch 封面 | `.media-switch.is-cover` | 一卡一眼，底部缩略图换主图 | 不进 Grid 格 |
| 因子公式 | `.formula` | 这个数怎么乘出来 | 尚未进 Grid 1–4 |
| Matrix | `.matrix` | 两轴四象限站哪格 | 尚未进 Grid 1–4 |
| Line Chart | `.line-chart` | 同一指标随时间怎么走 | 尚未进 Grid 1–4 |
| Venn | `.venn` | 集合怎么交 | 尚未进 Grid 1–4 |

编号列表纵向、Bar 纵向、表格长是 Content 变体，不是另一种分页。Grid 3 / 5+ 的编号列表用 `step-stack`，不要用横排 `step`。表格宽 / 表格长是同一种 `.content-cols`：列头 20 居中，单元格 20 左齐，列 hug、列间撑开；只改列数和行数。行数超出格子时在格内上下滚。Bar 组标题是 `.bar-compare__title`，20 Regular **居中**。Bar 和 Line Chart 的高度跟格子 fill，不要写死轨道/图高。

页面留白按分页不同，不是四周固定 200。稿上：1 格约 200×180；2 格约 348×82；3 格约 201×82；4 格约 360×0；5–9 吃满中间条带折行；10+ 左侧约 200、右侧溢出横滑。用格子上限（1520×544 / 600×720 / 490×720 / 588×430）居中，剩下来的就是边距。Matrix 左右轴「难做 / 好做」横排，不要 `rotate(90deg)`；上下轴横排居中，象限左齐。

多条列表 / 多步 = 多格，不要把一条拆成多列，也不要再包 `.block-set`。表和条的行数留在格内。

Evidence 三种素材：通用图默认 Fill；截图 `shot` + `0.46:1` Fit；宽/高 ≥ 2 用 `strip`。Media Switch 封面锁定 `9:16` Fill，文字浮层铺满图窗、不留边距。

### 分页 × Content

`可` = 能进这个分页。`禁` = 不许放。壳没有格子。全屏只放一块。

| Content | 非全屏 1 | 非全屏 2 / 3 / 4 / 5–9 / 10+ | 全屏 |
|---|---|---|---|
| 纯文字 | 可 | 禁 | 可 |
| 观点 | 可 | 禁 | 禁 |
| 带序号观点 | 可 | 可 | 禁 |
| 数据 | 可 | 可 | 禁 |
| 列表 | 可 | 可 | 禁 |
| 编号列表 | 可 | 可。Grid 3 / 5–9 / 10+ 用 `step-stack` | 禁 |
| 表格 | 可 | 可 | 禁 |
| Bar | 可 | 可 | 禁 |
| Evidence / Media Switch | 可（不进 Grid 格） | 禁 | 禁 |
| 公式 / Matrix / Line / Venn | 可（尚未适配 Grid 2–4） | 禁 | 禁 |

### 各分页里怎么展示

**封面 / 章封面 / 口径**  
壳自己排。不要往里面塞 Content。

**非全屏**  
`.page-grid` 包若干 `.grid-cell`，格数 = `data-slots`，格数 = 实例数。不许空格，不许混装。

| 分页 | 格子 | 格里怎么排 |
|---|---|---|
| 1 | Grid 1，扁卡约 1520×544 | 条带内左右 200、上下 136。表用宽表；Bar 用横条 |
| 2 | 两张 Grid 2，约 600×720 | 条带内左右 348、上下 33。表用少列；Bar 用竖条 |
| 3 | 三张 Grid 3，约 490×720 | 条带内左右 201、上下 33。编号列表用 `step-stack` |
| 4 | 四张 Grid 4，约 588×430 | 条带内左右 360、上下贴齐。2×2 |
| 5–6 | 三列折两行 | 五格末行居中；六格 3×2。编号列表用 `step-stack` |
| 7–9 | 更密的三列三行 | 七格末枚居中；八格末行两枚居中；九格 3×3。编号列表用 `step-stack` |
| 10+ | 若干 Grid 3，约 490×720 | 条带内左 200，右侧溢出横滑。编号列表用 `step-stack` |

1 格的观点 / 数据 / 带序号观点在格里居中。列表、编号列表左齐。

**全屏**  
永远 1 块。有图：图铺满，`data-caption="off"`，不是 Evidence，没有图注；字叠在中间。无图：浅底，一块纯文字。`.report-source` 贴在 `.full-page` 里、底边。

来源不是 Content。页壳三层和导航共用同一条边线 `--page-gutter`（1920 上是 200，小屏按 10.4vw，最低 64），格子也必须吃这条边，不许把卡拉到屏边。顶栏 Head 88、标题栏 88（左标题 20 / 副标题 12，右 `简介 · 屏号` 12）、底栏 Butt 88（数据来源 12，和副标题一档）。格子在中间条带里按卡尺寸居中。

稿上加了标题栏之后，中间 Grid 约 816（1 格）或 786（2/3/4/5–9/10+）。卡在条带里的留白：1 格 200×136；2 格 348×33；3 格 201×33；4 格 360×0；5–9 铺满条带折行；10+ 左 200、右溢出。不要再按旧的 884/904 条带算。

表：一种字段一列。标记和说明不是同一字段，不要写进同一格。列名写在表头或列首。不要 sticky 表头。

硬禁：

- 按演示一组件一屏切报告
- 绕过 `report.md` 直接从源文件出 HTML；稿和页各改各的
- 把父问句写宽来合并另一问
- `__part` 写组件名、更冲的句子，或把列名抄上去顶表头
- 把章题复制到每一屏当主标题
- 标题写成维度清单、口径缩写，或把屏上数字再念一遍
- 默认任务套强调皮肤；用屏号清单规定谁用强调
- 按条数自动换列，或用 `.block-set` 表示多组
- 把一条列表 / 编号列表拆成多列
- 一个 `.page-grid` 里混两种 Content，或留下空格
- 把 10+ 当成数量溢出的退路去折行；5–9 必须一次铺开
- 把全屏当成另一种 Grid 分组，或在全屏里放多格
- 发明新的分页，或把 `report-section__stack` / `report-split` 带进报告
- 加流式切换、加载 `flow.css`，或把 `.is-deck` 改成 `.is-flow`
- Formula 超过 5 个因子，Matrix 加第 5 格，Venn 加到 4 圈，Line Chart 画 3 条线
- 把公式 / Matrix / Line / Venn / Evidence 放进 2 / 3 / 4 / 5–9 / 10+ 或全屏
- Line Chart 用 `preserveAspectRatio="none"` 拉满格子，或去掉纵轴 / 图例 / 点
- Venn 用绝对定位圆顶到页底，或标签不落在各区中心

## 4. 工作流程

```
- [ ] 收资料（原文 / 大纲 / Inputs/<slug>/）
- [ ] 读懂每块的问句和角色，写出主判断
- [ ] 写 Outputs/<slug>/report.md（树 + 每节点的人话结论、注意力、形式、图链）
- [ ] 只组织 → 交稿，停
- [ ] 要页 → 按稿抄壳；不抄演示的切法
```

### 停下来问

- 主判断原文没有，或有好几句都像。
- 树还没梳清，或一枝抽出来问句不成立。
