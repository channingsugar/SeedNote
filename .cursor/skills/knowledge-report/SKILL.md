# Knowledge Report

报告的原子是听众的一步。演示的原子是一个父组件。抄演示的 markup，不抄演示的切法。

先读原文，写成带章节树、正文和图链的 Markdown，再按这份稿套模板。不要先挑组件，也不要按源目录的外形开 tab。

用户只要组织：交 Markdown 参考稿后停。用户要页：稿经确认（或对方说直接做）再写 `Outputs/<slug>/index.html`。HTML 只许从这份稿填，不许绕过它从源文件切片。稿和页必须是同一套；页若已存在，以稿为准重套，不要两份各改各的。

## 两套语法（禁止混用）

| | 演示页 `states-demo` | 报告 |
|---|---|---|
| 一屏是什么 | 穷举一种组件状态 | 做完听众的一个问句 |
| 标题下 `__part` | 可以写组件名 | 只放比主标题弱的范围或条件；没有就删 |
| 同一问里的多个同类对象 | 各占一屏，把组件走一遍 | 一屏并排，一次看完 |
| 怎么用它 | 抄 class 和结构 | 抄 class 和结构，不抄分页节奏 |

把演示的切法带进报告，就是把组件名写进标题、把同一问拆成逐个组件屏。

## 1. 内容组织

组织的不是文件，是听众脑子里的一条路：进门时不知道该信什么，出门时知道这件事是什么、凭什么、接下来怎么办。

源标题是作者怎么归档的，不是听众要走的路。读懂每一块在回答哪一问、担任什么角色，再精确成树。

| 这块在干什么 | 在树上的位置 |
|---|---|
| 立一个主张 | 自己成章，或做一章的开场 |
| 给某个主张付账 | 挂在那个主张下面，不另占导航 |
| 收成：现在该怎么办 | 自己成章。这是另一问 |
| 边界：材料不能支撑什么 | 自己成章，放在最后 |

读不准就标「待确认」并停问。不要用源标题平级当理解，也不要为了导航更短拿掉一整问。

### 章节树

分章是先画枝，不是先开 tab。导航从树长出来。树没梳清，不要切屏。导航写能看懂的章名，不要截成固定字数。选中用导航自己的皮肤，点击后不要留下浏览器描边。

**付账还是另一问，用这一句分：** 把这块单独抽出来，听众要完成的问句变了没有？

- 没变，只是数字、规则、现场、样本在给同一句付账 → 挂在这枝下面。
- 变了 → 另起一枝。兄妹是不同的问，不是孙节点。

禁止把父问句写宽来把另一问装进去。那不是付账，是合并。为了少开一档导航而合并，也算挂错。

回验：任一枝单独抽出来，问句还能否成立；整场标题连起来，能否听出一条路。

### 主判断怎么选

听众走出去能复述的一句。优先用原文。原文没有或有好几句都像，标「待确认」并停问。后面所有章都在给它付账。不要另写汇报腔，不要改数字和判断的松紧。

### 每一页怎么起标题

翻页时你先开口说一句，再让他们看。`__title` 就是那一句，不是这页的名字。

整场标题连起来，应该能听出一条路。抽掉图和表只念标题，听众还知道你要他们信什么。念完像目录、像字段、像把表读了一遍，这页还没起好。

一页只配一句。这句是判断、转折或取舍，有主语、有动作。他们离开时只记得大字，必须已经得到这页该给的东西。

| 槽 | 听众拿它当什么 | 往里放什么 |
|---|---|---|
| `__no` | 我现在在哪一章 | 章号 + 题域。分类名停在这里 |
| `__title` | 翻上来你开口那一句 | 能讲出口的判断、转折或取舍 |
| `__part` | 这句的范围或条件 | 比主标题弱的一句；没有就删 |

找标题的顺序不能反：

1. 先看这一屏材料，问：离开时只记得一句，应该是哪句。
2. 出声念。念不利索、要停下来解释这是什么意思，就还不是标题。
3. 回原文找作者已经写出来的判断。没有就待确认，不要编汇报腔。
4. 题域进 `__no` 或章封面。一屏一句，各自找，不要把章题复制到每一屏。

数字可以上标题，只在数字本身就是那一击的时候，并且说成人话里的多少、多贵、多窄。比较的维度、口径缩写、样本价、字段名是下面的证据，不抬到大字上。列名是表头的事，不要写进 `__part` 去顶包。

回验：只看大字，是不是人话，是不是这页该给的东西。大字是分类或维度清单、小字才是判断 → 槽位用反了。大字和材料对不上 → 用了邻屏或整章的句子。

### 强调级别

视觉重量必须等于命题重量。先问这一屏的任务，再选皮肤。

判断句：拿掉反色之后，听众是否少做了一个必须做的决定？是 → 强调。否 → 默认。拿不准 → 默认。

| 这一屏要听众干什么 | 重量 | 形式 |
|---|---|---|
| 改一个判断，只要一句 | 强调 | Decision Callout |
| 改判断，且必须并排钉住几句 | 强调 | Card Grid `.is-highlight` |
| 看懂并列事实、属性、对照、步骤 | 默认 | 普通卡、清单、表、步骤 |

强调不是「这章比较重要所以涂色」，也不是「章末自动升级」。默认皮肤能完成的任务，不要升级。重量用上面的判断句决定，不要在稿末用屏号清单规定谁用强调。

### 单屏

一屏一个问句，也只装一种形式。同一问的同类对象可以并排。一个形式装不下，就换屏，不要在一个格子里叠两个父组件。

图和字抢注意力，就选边：必须看清图 → 图当主角；必须读完字 → 字当主角；图是场景、字是一句判断 → 图铺满字收束；论证抽象 → 不要图。旁边的字离开图就不能成立，那是图注，不是配图页。

## 2. 参考稿（先写这个）

基于原文和大纲，先写 `Outputs/<slug>/report.md`。没有这份稿，禁止写 HTML。

稿里每一节点必须有：问句、能讲出口的结论、任务、注意力、重量、形式、正文、图的路径和说明。图链从原文 `src` / `data-src` / `data-lightbox-src` 收，再用 `find` 核磁盘；不要用 Glob 碰运气。

```markdown
# [报告名]

主判断：…

## 章节树

- 00 封面
- 01 [问句] · 主张
  - 01.a [开口那一句]
- 02 [问句] · 主张
- … 收成
- … 边界

## 01 [题域]

问句：
判断：

### 01.a

问句：
结论：
任务：判断 / 证据 / 比较 / 步骤 / 尺度 / 换气
注意力：图当主角 / 字当主角 / 图当底 / 只要字
重量：默认 / 强调
形式：
正文：
- …
图：
- `assets/…` — 说明
```

磁盘有、文中无的图：复制进 `assets/`，在稿里标缺口。听众没说拍板还是对齐事实，按对齐事实写，不加判断腔。

只组织：把这份稿交给用户，停。要页：按稿套模板，不按源 HTML 的外形切。不要在稿末另写一套「这些屏用强调、那些屏改标题」的清单，判断写在每一节点上。

## 3. 页面与父组件

形式跟着问句走。markup 从 `templates/editorial-default/` 抄壳。模板按分页穷举父组件：标题是组件名，副题是使用场景。报告抄 class 和结构，不要按它一组件一屏切。Evidence 多一种比例时打开 `templates/states-demo/`。样式拷到 `Outputs/<slug>/lib/`。不要输出去读 `../../design-system/`。

先选分页，再往格子里放**一个**父组件。不要发明第七种分页，也不要在一个格子里叠两个父组件。`report-section__stack` 和 `report-split` 不是分页，不要抄。不要给 Card / Callout 加装饰线。

### 分页（只有这些）

| 分页 | markup | 这一屏是什么 |
|---|---|---|
| 封面 | `.report-cover` | 整场开场。壳，没有格子 |
| 章封面 | `.chapter-cover` | 换气。壳，没有格子 |
| 口径 | `.report-notes` | 边界。最后一章，导航里有这一档。壳，没有格子 |
| 1 分区 | `.page-regions[data-regions="1"]` | 一个格子，铺满标题下的内容区 |
| 配图 · 左右 | `[data-media-page="split"]` | 左图右文，各占 1/2。图槽不是 Evidence，不显示图注 |
| 配图 · 上下 | `[data-media-page="stack"]` | 图铺满当底，标题叠在图上；底部定高只排 1 行。图槽不是 Evidence，不显示图注 |

当前这版 OUTPUT 的内容屏全部是 **1 分区**。左右 / 上下系统有，这版没用。选分页仍按问句，不要为了用上配图页硬切。

### 父组件（只有这些）

| 父组件 | class | 什么时候用 |
|---|---|---|
| Decision Callout | `.callout` | 改一个判断，只要一句 |
| Card Grid | `.card-grid` | 并列要点，一卡一眼 |
| Card Grid · 强调 | `.card-grid.is-highlight` | 必须并排钉住的几句判断 |
| Stat Grid | `.card-grid` + `.stat-value` | 尺度。数字行只放数字或符号 |
| Labeled List | `.list-block` | 属性、规则、条目 |
| Process Steps | `.steps` | 有先后的步骤 |
| Data Table | `.table-wrap` > `.data-table` | 比较表 / 明细表 |
| Bar Compare | `.bar-compare` | 同类量比较。默认横条，竖条加 `.is-vertical` |
| Evidence | `.image-grid.evidence-gallery` > `.evidence-figure` | 图 + 图注 |
| Media Switch 封面 | `.media-switch.is-cover` | 一卡一眼，底部缩略图换主图 |
| 默认文案 | `.media-page__copy` | 只出现在配图页的字槽 |

Evidence 三种素材：通用图默认 Fill；截图 `shot` + `0.46:1` Fit；宽/高 ≥ 2 用 `strip`。Media Switch 封面锁定 `9:16` Fill，文字浮层铺满图窗、不留边距。

### 分页 × 父组件

`可` = 能进这个格子。`禁` = 不许放。壳没有格子。

| 父组件 | 1 分区 | 左右 · 右 | 上下 · 底 |
|---|---|---|---|
| Callout | 可 | 禁 | 可 |
| Card Grid | 可 | 禁 | 可 |
| Card Grid · 强调 | 可 | 可 | 可 |
| Stat Grid | 可 | 禁 | 可 |
| List | 可 | 可 | 禁 |
| Steps | 可 | 可 | 禁 |
| Table | 可 | 禁 | 禁 |
| Bar Compare | 可 | 可 | 禁 |
| Evidence | 可 | 禁（图槽用光图） | 禁（图槽用光图） |
| Media Switch 封面 | 可 | 禁 | 禁 |
| 默认文案 | 禁 | 可 | 可 |

左右的图槽、上下的图槽：只放一张光图，`data-caption="off"`，不是 Evidence，没有图注。只有图注、离开图字就不成立 → 用 1 分区 Evidence，不要做成左右。

### 各分页里怎么展示

**封面 / 章封面 / 口径**  
壳自己排。不要往里面塞父组件。

**1 分区**

| 父组件 | 展示 |
|---|---|
| Callout | 整块在格子里居中，不拉满。字号随格子变 |
| Card / Stat | 铺满格子宽度。一行时高度有上限，在格子里居中。多行按内容高度 |
| Card · 强调 | 铺满宽度，反色。不要再套一层白底 |
| List / Steps | 整块按最长一条定宽，在格子里水平、垂直居中。条目左对齐共一条边，不要每条单独居中。超过 5 条顶对齐，格子里上下滚。字和分割线同宽。行按内容高度，不拉满。最后一条下面不画线 |
| Table / Bar | 铺满格子宽度。条数少时整块垂直居中；超过 5 条顶对齐，格子里上下滚。行按内容高度，不把表拉满再均分。最后一行下面不画线 |
| Evidence | 图在上、图注在下、图注居中。多张并排；放不下横滑，首尾留白，右侧渐隐。通用图 Fill；`shot` 锁定 `0.46:1` Fit；`strip` 横滑 |
| Media Switch 封面 | 一张或 N 张并排。封面 `9:16` Fill。展开后浮层铺满图窗。缩略图贴底边 |

**配图 · 左右**  
左图 Fill 满格。右侧一个父组件，留间距后铺满右格。

| 右侧 | 展示 |
|---|---|
| 默认文案 | 标题 / 正文 / 来源，铺满右格 |
| List / Steps | 铺满右格，条目左齐，超过 5 条顶齐可滚 |
| Card · 强调 | 贴边铺满右格，最多 6 张 |
| Bar Compare | 铺满右格，默认横条 |

**配图 · 上下**  
图铺满整页当底。底栏定高、只排 1 行。

| 底栏 | 展示 |
|---|---|
| 默认文案 | 深色毛玻，水平居中 |
| Callout | 浅色毛玻，水平居中 |
| Card / Stat | 浅色毛玻，铺满底栏 |
| Card · 强调 | 贴边 |

表：一种字段一列。标记和说明不是同一字段，不要写进同一格。列名写在表头，表头就是第一行，打开就能看见。不要 sticky 表头。首列标签不折行。正文在格子里换行。列宽按字段收，剩余宽度给最后一列。表头保持横排。

硬禁：

- 按演示一组件一屏切报告
- 绕过 `report.md` 直接从源文件出 HTML；稿和页各改各的
- 把父问句写宽来合并另一问
- `__part` 写组件名、更冲的句子，或把列名抄上去顶表头
- 把章题复制到每一屏当主标题
- 标题写成维度清单、口径缩写，或把屏上数字再念一遍
- 默认任务套强调皮肤；用屏号清单规定谁用强调
- 截图 / 条带左右切半或上下满铺
- 只有图注做成左图右文
- 左右放普通 Card Grid、Data Table
- 上下放 List、Steps、Table、Bar
- 一个格子里叠两种父组件
- 两种字段挤进同一格
- 把 List / Steps / Table / Bar Compare 有的顶齐、有的居中，或把行拉满制造空线
- 发明第七种分页，或把 `report-section__stack` / `report-split` 双块叠法带进报告

## 4. 工作流程

```
- [ ] 收资料（原文 / 大纲 / Inputs/<slug>/）
- [ ] 读懂每块的问句和角色，写出主判断
- [ ] 写 Outputs/<slug>/report.md（树 + 每节点的人话结论、注意力、形式、图链）
- [ ] 只组织 → 交稿，停
- [ ] 要页 → 按稿抄壳；不抄演示的切法
```

### 停下来问

- 主判断原文没有，或有好几句都像。
- 树还没梳清，或一枝抽出来问句不成立。
- 父问句被写宽，另一问被装进去了。
- 某一屏的标题念不利索，或只是字段和数字。
- 图对不上任何一句。
- 重量拿不准，且升到强调和保持默认差很多。
- 没说只要组织还是要页。

做完只报告：`report.md` 路径、主判断、树的章数、HTML 路径（若已做）、屏数、缺口。
