# Knowledge Report

先组织内容，再派单屏任务，再决定眼睛看谁，再选形式，最后按流程落到现有壳上。不要先挑版式。

用户只要组织：做到第 5 章的屏清单就停。用户要汇报页：屏清单经确认（或对方说直接做）再写 `Outputs/`。

## 1. 内容组织

组织的不是文件，是听众脑子里的一条路：进门时不知道该信什么，出门时知道这件事是什么、凭什么、接下来怎么办。

不要按「我们做了什么」的时间线讲，按**听众要做的判断**讲。作者原来的章节名可以留，顺序可以动。动的依据只有一个：听众下一秒需要什么，不是文件夹里下一份是什么。

### 骨架

1. **为什么现在讲这个** — 一句话点出利害，不讲背景史。
2. **整场只立一个主判断** — 听众走出去能复述的那一句。后面所有章节都在给它付账。
3. **先给地图** — 「今天三件事」说完，听众才肯把注意力交给你。章数少，宁可 3 段讲透，不要 8 段报流水。
4. **一章只打一个点** — 每章一个主张，主张下面才是证据。主张和证据不要叠在同一口气里。
5. **让他们看见对立面** — 我们看过什么、为什么不走那条。信任来自取舍，不是来自材料多。
6. **收成动作或边界** — 现在该做什么，以及这份材料不能支撑什么。没说清边界，前面的判断都会被听成吹。

### 技巧

**先写能讲出口的稿，再切屏。**  
先用口语把整场过一遍，每段只留一句能喊出来的话。这句话才是这一屏的标题。标题是结论，不是题目。「陆运」是题目；「陆运解决的是分离焦虑，不是时效」才是结论。

**一屏一件事。**  
听众不能同时读一段长文、看一张细图、消化三个数字。数字证明尺度，图证明现场，表证明比较，判断证明你要他们信什么。两件就要拆。同一件事的数字和明细表可以待在一起，因为它们在付同一笔账。

**先给看什么，再给看。**  
复杂图、截图、对照表，先用一句话说「请看这个」，再亮出来。没被指引的细节等于没出场。

**图和字抢同一条注意力，就选边。**  
- 听众必须看清图里的东西（界面、流程、现场细节）→ 图当主角，字只当图注或另开一屏判断。
- 听众必须读完规则、步骤、比较 → 字当主角，图只负责让人知道「说的是这个东西」。
- 图是场景、字是一句判断 → 图铺满，字压在上面，当气氛和收束，不当说明书。
- 论证是抽象的（口径、条件、数字、取舍）→ 不要图。空图比没图更伤。

**对比比罗列有力。**  
能做成 A/B、能/不能、贵/快/稳，就不要做成 7 条并列。并列超过 5 条，听众会当成清单，不当成判断。

**重复主判断，换证据，不换命题。**  
每章开头用不同材料把同一句话再钉一次。换措辞会让人以为你在立新主张。

**留换气。**  
章与章之间要有空拍：一句章名、一句这一章要解决什么。连续抛证据，听众会积压，不会积累。

**少说过程，多说取舍。**  
「我们调研了三周」没有信息。「这三条路里，只有这条过得了检疫」才有信息。过程留在问答。

### 动手前先问四句

桌上摊开所有句子和所有图，不问「这页好看吗」，问：

1. 这场结束时，听众必须带走哪一句？
2. 这句话靠哪几块材料才能成立？其余做附录或删掉。
3. 每一块里，听众该看图，还是该读字？
4. 看完这一块，他们是更接近主判断了，还是只是多知道了一个事实？

过不了第 4 问的，就是展览，不是演讲。四句答不清，不要开始做页。

## 2. 单屏任务

章节组织只解决先讲什么。呈现从这里开始：给每一屏派一个任务。

这一屏只干一件事。先点名，再选形式：

| 任务 | 这一屏要听众干什么 |
|---|---|
| 判断 | 信这一句 |
| 证据 | 看见凭什么 |
| 比较 | 看出差别或取舍 |
| 步骤 | 跟上顺序 |
| 尺度 | 建立量级 |
| 换气 | 知道下一章打什么 |

主张和证据不要叠在同一屏。同一件事的数字和明细表可以待在一起，因为它们在付同一笔账。两件就要拆。

任务说不清，禁止选版式。

## 3. 注意力

任务定了，决定这一屏的眼睛给谁。图和字抢同一条注意力，必须选边。

先问：旁边的字离开图还能不能成立。只能当图注，图就是主角，不是配图页。

| 听众这一刻该干什么 | 注意力给谁 | 版式 |
|---|---|---|
| 看清图里的东西（界面、流程、现场细节） | 图当主角 | 图 + 图注；判断另开一屏 |
| 读完规则、步骤、比较 | 字当主角 | 字为主；有图则旁挂，说明「说的是这个」 |
| 感到场景，收下一句判断 | 图当底，字收束 | 图铺满，字压在上面，不当说明书 |
| 消化口径、条件、数字、取舍 | 只要字 | 不要图。空图比没图更伤 |

图里的字还读不读得清。读不清，版式选错了：截图、条带、必须看清的字，不要铺满、不要切半。

不要为了填屏把已经选对的边对调，也不要找一张无关图硬配。

## 4. 形式

任务和注意力定了，再用能装下它们的形式。形式跟着任务走，不要反过来改稿去填格子。

| 任务 + 注意力 | 形式 |
|---|---|
| 判断，只要字 | 一句结论，单独一屏 |
| 判断，图是场景 | 图铺满 + 那句结论压上去 |
| 证据，图里有要看的东西 | 图当主角，图注跟着图 |
| 字当主角，旁边有一张能说明「是这个」的图 | 左图右文（竖图 / 方图 + 要读完的内容） |
| 并列要点 | 清单或卡片，不要超过 5 条还当判断讲 |
| 顺序 | 步骤 |
| 比较 / 取舍 | 对照，能 A/B 就不要 7 条并列 |
| 尺度 | 数字；和它的明细表可以同屏 |
| 换气 | 章名 + 这一章要解决什么 |

形式装不下（长步骤塞进底栏、截图铺满被裁、只有图注却做成左图右文），就换形式或拆屏。不要为了填满去改句子、裁掉必须看清的东西、或把无关两块拼在一起。

标题仍是能喊出来的那句结论，不是题目。作者的标题、判断、数字、图注不改写；换的是壳，不是稿。

### 回验

看着这一屏，还能不能喊出这一段的那句结论。喊不出来，回去查任务、注意力、形式，哪一环没对上。不要先改装饰。

## 5. 工作流程

```
- [ ] 收资料
- [ ] 问清四句（第 1 章）；问不清就停
- [ ] 写出屏清单（第 2–4 章）
- [ ] 只组织 → 把清单交给用户，停
- [ ] 要页 → 复制壳和图，按清单填，不发明页面
```

### 收资料

- 源：用户粘贴的大纲 / HTML，或 `Inputs/<slug>/`。
- 抽出作者的标题、段落、列表、表、数字、图注。丢掉的只有源 CSS 和布局 class。
- 图不要用 Glob 判断有没有。列 HTML 的 `src` / `data-src` / `data-lightbox-src`，再用 `find` 列磁盘上的 jpg/png/webp/gif。两份都要进清单。
- 听众没说：先问是拍板、对齐事实，还是留档。不问就按「对齐事实」做，不要擅自加判断腔。

### 改到哪为止

| 可以 | 不可以 |
|---|---|
| 按听众重排章节、合并或拆屏 | 改数字、改判断的松紧、另写汇报腔 |
| 从原文里选一句当屏标题 | 把题目改写成原文没有的结论 |
| 选用已有壳和父组件 | 发明页面种类或页面级自定义布局 |

拿不准的标题标「待确认」，写进屏清单问用户。不要先改再问。

### 停下来问

- 主判断原文没有，或有好几句都像。
- 图在文中对不上任何一句（未标注归属）。
- 听众不明，且两种排法差很多。
- 用户没说只要组织还是要页。

### 屏清单

做页之前先交这张表。用户没说「直接做」时，等他看过再写 HTML。

```
| 屏 | 章 | 结论句（原文或待确认） | 任务 | 注意力 | 形式 | 原文块 | 图 |
| 0 | — | 原 h1 | 换气 | 只要字 | 报告封面 | … | — |
| 1 | §2 | 原 h2 | 换气 | 只要字 | 章节封面 | … | — |
| 1.a | §2 | 原句… | 尺度 | 只要字 | 数字 | B01 | — |
| 1.b | §2 | 原句… | 证据 | 图当主角 | 图+图注 | B02 | cabin.jpg |
```

磁盘有、文中无的图：复制进 `assets/`，清单标缺口，不要擅自安插。

### 做页

输出：`Outputs/<slug>/`。

```
Outputs/<slug>/
  index.html
  assets/          # cp -R 源 assets，不要手挑
  lib/             # 从模板复制，见第 6 章
```

按屏清单填原文和图。做完只报告：输出路径、屏数、形式用了哪些、图复制了多少、缺口。

## 6. 形式对照

壳和分区只许用这些。markup 从 `templates/editorial-default/` 和 `templates/states-demo/` 抄，样式从 `templates/shared/components.css` + `templates/editorial-default/assets/` 复制到 `Outputs/<slug>/lib/`。设计系统「页面」tab 是对照，不要输出去读 `../../design-system/`。

### 壳

| 形式 | 用这个 |
|---|---|
| 整场开场 | 报告封面 `.report-cover` |
| 换气 | 章节封面 `.chapter-cover` |
| 口径 / 边界 / 缺口 | 口径说明 `.report-notes`（最后一屏） |

分片外壳：`.report-shell.is-deck` → 顶上章节 tab → `.report-slide`。导航标签用作者章名的缩短。

### 分片

| 第 4 章的形式 | 分区 | 父组件 |
|---|---|---|
| 判断，只要字 | 1 分区 | Decision Callout |
| 判断，图是场景 | 配图 · 上下 | Callout（底栏） |
| 图 + 图注 | 1 分区 | Evidence |
| 一卡一眼 + 缩略图 | 1 分区 | Media Switch 封面 |
| 截图 / 条带 | 1 分区 | Evidence（`shot` / `strip`） |
| 左图右文 | 配图 · 左右 | 右侧：默认文案 / List / Steps / 强调网格 / Bar |
| 并列要点 | 1 分区 | Card Grid 或 Labeled List；强调用 `.is-highlight` |
| 步骤 | 1 分区 | Process Steps |
| 比较表 | 1 分区 | Data Table |
| 同类量比较 | 1 分区或左右 | Bar Compare |
| 尺度 | 1 分区 | Stat Grid |
| 尺度 + 同一件事的明细表 | 1 分区叠两块，或 2 分区上下 | Stat + Table |

硬禁（形式装不下）：

- 截图、条带、必须看清的字 → 不要左右切半，不要上下满铺
- 只有图注 → 不要左图右文
- 左右不要放普通 Card Grid、Data Table
- 上下不要放 List、Steps、Table、Bar
- 不要发明「封面图卡 / 同级双块 / 判断单独页」这类页面种类

图：通用图默认 Fill；截图锁定 `shot` + `0.46:1` Fit；宽/高 ≥ 2 用 `strip`。细则看演示页，不要凭感觉 cover。
